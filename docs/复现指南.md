# 复现指南 —— 从零到跑通数据采集

> 本文回答一个问题：**甲方拿到本仓库后，怎样一步步复现出我们这边的遥操作与数据采集。**
>
> 结论先说：**源码层面可以完整复现；但有几项环境前提不在仓库里，必须由甲方侧具备**
> （OrcaStudio 本体、OrcaLab 账号与资产订阅、支持的硬件）。第四节逐项列清。

---

## 一、前置条件（硬门槛）

以下四项**无法通过仓库提供**，必须先具备，否则后面的步骤都跑不起来：

| # | 前置项 | 说明 | 由谁提供 |
|---|---|---|---|
| 1 | **OrcaStudio / OrcaLab 26.8.1** | 仿真器本体，商业软件，Windows 专有。含 `orca_gym` / `orcalab-pyside` Python 包与 gRPC 服务 | 松应科技（OrcaLab 官方） |
| 2 | **OrcaLab 账号 + 资产订阅权限** | 场景依赖的资产包（桌面 / 机器人 / 药物 / 托盘 / 相机）从云端资产库按需下发，需登录并订阅 | 松应科技 + 甲方账号 |
| 3 | **硬件** | 独显（我们实测 RTX 4060 Laptop 8 GB 可用）、≥32 GB 内存、CPU 性能足够；另需手柄（XInput）或键盘 | 甲方自备 |
| 4 | **网络** | 首次打开场景需访问资产库拉取 `.pak`（总量约 850 MB） | 甲方环境 |

> **版本一致性是关键**：OrcaStudio 与我们使用的 `orca_gym==26.8.1` 必须同版本。
> 版本不一致时，gRPC 协议、物理模型、相机接口都可能对不上，表现为连接失败或
> 关节名找不到。我们的环境清单见仓库根的 `environment.yml`。

## 二、环境搭建

### 2.1 安装 OrcaStudio

按松应科技提供的安装包安装 OrcaLab / OrcaStudio **26.8.1**，装完后：

- 安装器会自动下载 Miniconda 并创建 conda 环境（见安装目录下的 `orcalab.bat`）。
- 环境名按我们的命名为 **`orcalab281`**（Python 3.12.13）。若安装器建的环境名不同，
  记下实际路径，后续命令替换即可。

### 2.2 克隆仓库

```powershell
git clone https://github.com/yuzhanjianwen-ops/orcalab-manipulation.git
cd orcalab-manipulation
```

仓库为 **Public**，克隆下来共 **179 个文件 / 约 1.6 MB** —— 只有源码、场景 JSON、
文档与环境清单；数据集与二进制资产由 `.gitignore` 排除（原因见 3.1）。

本文内容对应的**基线提交**为 `b3c282e`（2026-10-15），它包含全部代码与复现链路修复；
其后的文档同步提交不影响本文的复现步骤。若克隆后内容与本文描述对不上，先确认自己
是否在 `main` 分支上。

### 2.3 重建 Python 环境

两种方式，任选其一：

```powershell
# 方式 A（推荐）：按环境清单精确重建
conda env create -f environment.yml

# 方式 B：在已有 orcalab281 环境里补齐缺失包
& "<你的python.exe>" -m pip install -r requirements-lock.txt
```

`environment.yml` / `requirements-lock.txt` 锁定 **170 个包**的精确版本，
关键版本为：

| 包 | 版本 | 来源 |
|---|---|---|
| `orca-gym` | 26.8.1 | OrcaStudio 安装 |
| `orca-lab` | 26.8.1 | OrcaStudio 安装 |
| `orcalab-pyside` | 26.8.1 | OrcaStudio 安装 |
| `mujoco` | 3.12.0 | 依赖 |
| `gymnasium` | 1.2.1 | 依赖 |
| `numpy` | 2.2.6 | 依赖 |
| `scipy` | 1.16.2 | 依赖 |
| `h5py` | 3.16.0 | HDF5 落盘 |
| `av` | 15.1.0 | 相机流解码 |
| `lerobot` | 0.6.2 | LeRobot v3.0 落盘 |

> **`orca_gym` / `mujoco` / `gymnasium` 不要单独 pip 安装** —— 它们由 OrcaStudio
> 环境提供，单独装极易版本错位。

### 2.4 命令必须加 `-X utf8`

代码与日志含中文，**所有 python 调用都要带 `-X utf8`**，否则会 `UnicodeEncodeError`。
下文所有命令均已包含。

## 三、加载场景与资产同步

### 3.1 认识资产路径

场景 JSON 里的路径形如：

```
assets/e071469a36d3c8aa/simplemovement_screw/.../Table
```

**这是一个虚拟路径，不是仓库里的真实目录。** 资产的真实来源是 OrcaLab 云平台的
`.pak` 包，由 OrcaStudio 依据场景的 `package_references` 字段自动下载解包到：

```
%LOCALAPPDATA%\Orca\OrcaStudio\<工程GUID>\user\downloaded_packages\
```

因此**仓库不需要、也不包含 330 MB 的机器人资产**。

### 3.2 订阅资产包

主场景 `scenes/SimpleMovement2.json` 依赖 5 个包，需在 OrcaLab 资产库中订阅：

| 包 ID（前缀） | 名称 | 内容 | 体积 |
|---|---|---|---|
| `fff12a1f` | SimpleMovement_Screw | 桌面 / 场景底座 | ~455 MB |
| `2589f665` | g1_omnipicker | 双臂协作服务机器人 | ~63 MB |
| `a284e930` | Medical | 药盒 / 药瓶（33 个） | ~33 MB |
| `3a46ef91` | simple_empty_kitchen | 木格托盘所在包 | ~302 MB |
| `8c216d8b` | camera | 相机资产 | ~3 KB |

### 3.3 加载主场景

1. 启动 OrcaStudio。
2. 打开场景文件：`scenes/SimpleMovement2.json`（★ 主场景）。
3. 等待资产同步完成。若控制台出现
   「跳过 /<实体名>，资产 <路径> 不存在」→ 说明对应资产包**未订阅或未下载完**，
   回到 3.2 检查订阅状态。
4. 确认场景树中有这些实体（主场景共 11 个）：

   ```
   Group / Static_Objcets / Table
   Interactive_Objcets
   dual_arm_collaborative_service_robot_1   ← 机器人
   qiangli_pipalu_medication_box_1          ← 药盒
   calcium_gluconate_tablets_bottle_1       ← 药瓶
   wooden_lattice_tray_1                    ← 木格托盘
   head_camera_1 / wrist_camera_l / wrist_camera_r   ← 三台静置相机
   ```

### 3.4 资产巡检工具（可选）

仓库自带巡检与修复脚本，跨机器部署时建议先跑一遍：

```powershell
cd scenes
& "<你的python.exe>" -X utf8 _pkg_check.py                 # 巡检：列出缺失资产
& "<你的python.exe>" -X utf8 fix_scene_asset_paths.py --dry-run   # 预演修复
& "<你的python.exe>" -X utf8 fix_scene_asset_paths.py --apply     # 实际写入（自动备份）
```

## 四、跑通遥操作与数据采集

### 4.1 遥操作（手柄）

```powershell
cd scripts\teleop
& "<你的python.exe>" -X utf8 -u teleop.py --flip-lr
```

### 4.2 遥操作（键盘）

```powershell
cd scripts\teleop
& "<你的python.exe>" -X utf8 -u teleop.py --keyboard --flip-lr
```

> `--flip-lr`：**相机在机器人背后时必须加**（我们现场就是这个配置）。
> 前后反了再加 `--flip-fb`。

### 4.3 采集（HDF5 格式，默认）

```powershell
cd scripts\collect
& "<你的python.exe>" -X utf8 -u collect.py --keyboard --flip-lr
```

产出结构：

```
data/dataset/<YYYY-MM-DD_HHMMSS>_<短uuid>/
├── episode.hdf5     每帧数据（joint_pos / joint_vel / gripper_pos / ee_pos / ee_quat / action_* …）
└── meta.json        episode 元信息（帧数、时长、任务名、字段清单）
```

### 4.4 采集（LeRobot v3.0 格式）

```powershell
cd scripts\collect
& "<你的python.exe>" -X utf8 -u collect_lerobot.py `
    --keyboard --flip-lr --lerobot-out D:/data/lerobot/pick_medbox
```

产出为标准 LeRobot 数据集（parquet + 视频），可直接用于训练。
详见 `docs/LeRobot3.0采集使用说明.md`。

### 4.5 运行自检

```powershell
cd tests
& "<你的python.exe>" -X utf8 run_all_tests.py
```

## 六、已知无法通过仓库覆盖的事项

这几项属于**环境/资产侧**，不是代码问题，需要甲方或松应科技介入：

| # | 事项 | 现象 | 需要谁做什么 |
|---|---|---|---|
| 1 | **`camera_head` 安装位姿异常** | 引擎离屏渲染该相机时画面为机器人头部外壳内壁（全黑），与编辑器视口不一致。根因：父节点 `/dual_arm_collaborative_service_robot_1` 的 `scale = 1.695356845855713` 未正确作用于相机偏移，实测需外移约 0.3 m。左右腕相机两条链路一致（PASS）。 | 在 Studio 里把 `camera_head` 沿视线外移约 0.3 m 并保存场景；或在**场景根节点**（scale=1.0）新建头部视角相机 |
| 2 | **`ncam = 0`** | MuJoCo 物理模型里相机数为 0，引擎相机不依赖 MJCF `<camera>`，靠 Studio 侧占位 body + `SetCameraSensorInfo` 激活 → **改 MJCF 无效** | 在 Studio 侧改相机实体 |
| 3 | **物理层缺物体** | 物理 body 只有 Table + 机器人（65 个），**不含**托盘 / 药盒 / 药瓶 —— 它们在渲染层存在但未进物理层，抓取时不会产生接触 | 确认这些物体是否需进物理层；若需要，在 Studio 里为其配置碰撞体 |
| 4 | **相机图像字段为空** | 采集字段 `image` 已预留但当前无数据（依赖第 1 项修复） | 修复第 1 项后重跑采集 |
| 5 | **机器人型号不在甲方清单** | 我们用的 `dual_arm_collaborative_service_robot_1`（G1 OmniPicker，双臂 7+7）不在甲方 `RobotProfile` 已知型号列表内 | 确认是否需要适配 |

> 相机链路的完整诊断（含实测证据链）见
> `scripts/collect/相机取图根因结论与修复方案.md`。
> 修复后可用 `scripts/collect/_verify_cam_fix.py` 一键验收
> （输出三联对照图，diff < 40 记 PASS）。
