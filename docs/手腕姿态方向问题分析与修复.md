# 手腕姿态控制方向异常 — 问题分析与修复报告

- **日期**：2026-09-23
- **问题模块**：`teleop.py` 手柄遥操作程序 — 右摇杆（手腕姿态）控制
- **状态**：已修复并实测验证

---

## 1. 问题现象

操作者使用手柄遥操作时，反馈**姿态控制方向不对**：

| 现象 | 描述 |
|---|---|
| 主要症状 | 右摇杆往左推 → 手腕实际**往右**转；往右推 → 手腕**往左**转 |
| 伴随症状 | 俯仰（pitch）操作手感"怪"，不是干净的单轴旋转 |
| 关键特征 | **按 R3 切换视角方案无效**，无论怎么切方向都相反 |

前期已处理过"平移方向反向"问题（通过视角方案切换解决），
但**手腕旋转的问题始终无法通过切换视角消除**，说明成因不同。

---

## 2. 排查过程

### 2.1 第一步：检查摇杆到控制量的映射链路

定位到 `teleop.py` 运动控制段，发现视角处理只作用于左摇杆：

```python
lx, ly = self.pad.left
rx, ry = self.pad.right
lx, ly = self.view.apply(lx, ly)   # ← 只有左摇杆被镜像
...
w = np.array([rx, ry, ...])        # ← 右摇杆直接用原始值
```

**发现**：`view.apply()` 完全没有作用于右摇杆。

同时查阅 `teleop_view.py` 的设计注释，其中明确写道：

```text
Vertical (RT/LT) and wrist rotation are never touched.
```

这证实**"手腕旋转不参与视角镜像"是当初的有意设计**，而非笔误。

### 2.2 第二步：判断该设计是否成立

该设计隐含一个前提：**手腕旋转与水平面镜像无关**。

**这个前提是错误的。** 手腕的 yaw（左右转）就是绕**垂直轴**旋转，
它和平移的左右方向属于**同一类镜像**——从背后看时，yaw 的方向必然也反转。

因此：**不是代码写错，而是当初的设计遗漏了 yaw 这一项。**

这也解释了为什么按 R3 切换视角无效——右摇杆根本没接入视角逻辑。

### 2.3 第三步：定位"手感怪"的更深层原因

继续核查旋转的计算方式：

```python
M = rot_z(w[0] * dt) @ rot_y(w[1] * dt) @ rot_x(w[2] * dt)
self.goal[side][1] = M @ self.goal[side][1]      # ← 左乘
```

**左乘 `M @ R` 的几何含义是：绕【世界（base）固定轴】旋转。**

而操作者期望的"手腕俯仰 / 左右转 / 滚转"，是绕**末端自身轴**旋转。

两者在末端姿态未对齐时会产生偏差。实测机器人底座朝向：

```text
底座 rotation = (-0.1496, -0.8462, -177.019)
```

绕 Z 轴为 **-177.019°**，并非精确的 -180°，存在约 **3° 的偏斜**。
用世界轴代替末端轴时，各轴都会产生偏差：

| 旋转轴 | 代码实现 | 与末端实际轴的关系 | 结果 |
|---|---|---|---|
| yaw | `rot_z` | 世界 Z ≈ 末端垂直轴，但方向镜像 | **方向必错** |
| pitch | `rot_y` | 世界 Y ≈ 末端左右轴，偏斜约 3° | 伴随横向漂移，手感怪 |
| roll | `rot_x` | 世界 X 与末端前向轴反向 | 方向可能相反 |

**左乘还有一个固有缺陷**：旋转轴始终固定在世界系，
所以**末端姿态越歪，手感越不一致**，无法形成稳定的肌肉记忆。

### 2.4 第四步：数学验证

对 `rot_z` 的符号约定做数值验证：

```text
rot_z(+30°) 把 +Y 向量转到 → [-0.5, 0.866, 0]   （转向 -X 方向）
XInput 约定：右推右摇杆 → rx > 0
因此：右推 → rx>0 → rot_z(正角) → 末端朝左转
```

**与操作者描述的"往右推往左转"完全吻合**，确认 yaw 符号需要修正。

---

## 3. 根本原因

问题由**两个独立缺陷叠加**造成：

### 缺陷一：yaw 未接入视角镜像（方向必定反）

`view.apply()` 只处理左摇杆（平移），右摇杆的 yaw 完全未处理。
而 yaw 作为水平面旋转，与平移左右属于同一类镜像，**逻辑上必须一并翻转**。

### 缺陷二：旋转轴使用世界轴而非末端轴（手感"怪"的根源）

原代码采用**左乘**，即绕世界固定轴旋转。而手腕动作的直觉是绕末端自身轴旋转。
在底座存在约 3° 偏斜的情况下，各轴均产生偏差，且手感随姿态变化而不稳定。

---

## 4. 修复方案

### 4.1 修复一：yaw 跟随视角镜像

```python
lx, ly = self.view.apply(lx, ly)
# yaw is a horizontal rotation, so it mirrors with the view
# exactly like the left/right translation axis does.  Pitch
# and roll stay put.
if self.view.flip_lr:
    rx = -rx
```

**注意**：只翻转 yaw（`rx`），**pitch（`ry`）和 roll（RB/LB）保持不变**。
因为 yaw 是水平面旋转，而 pitch 和 roll 不涉及左右镜像。

### 4.2 修复二：旋转改为绕末端自身轴（右乘）

```python
w = np.array([rx, ry, self.pad.held("RB") - self.pad.held("LB")]) * ANG_SPEED
# The wrist rotates about the TOOL's own axes, not the
# world axes: right-multiplying keeps "push left -> turn
# left" true no matter how the hand is already oriented.
M = rot_z(w[0] * dt) @ rot_y(w[1] * dt) @ rot_x(w[2] * dt)
self.goal[side][1] = self.goal[side][1] @ M      # ← 原来是 M @ self.goal[side][1]
```

**改动点**：把 `M @ R`（左乘）改为 `R @ M`（右乘）。

改动后三个旋转轴的含义变为：

| 旋转轴 | 修复后含义 |
|---|---|
| yaw | 绕**末端自己的垂直轴**转（就是手腕左右转） |
| pitch | 绕**末端自己的左右轴**转（手腕俯仰） |
| roll | 绕**末端自己的前向轴**转（手腕滚转） |

三个轴全部对应"手腕自身"的动作，与操作者直觉一致，
且**不再随末端姿态变化而漂移**。

### 5.2 现场实测（操作者确认）

最终确认的现场配置为 **`--flip-lr`**（相机位于机器人背后）：

| 控制轴 | 修复前 | 修复后 |
|---|---|---|
| 左摇杆 左右 | 需切换视角 | **正确** |
| 左摇杆 前后 | 需切换视角 | **正确** |
| 右摇杆 yaw（左右） | **反向** | **正确** |
| 右摇杆 pitch（俯仰） | 手感怪 | **正确** |
| 右摇杆 roll（滚转） | 未确认 | **正确** |

**五个方向全部正确。**

### 5.3 一个重要发现：`--behind` 与 `--flip-lr` 的适用区别

实测中发现一个容易混淆的点：

| 参数 | 翻转范围 | 适用场景 |
|---|---|---|
| `--behind` | 左右 **和** 前后**都翻** | 站在机器人**正对面**（前后左右全反） |
| `--flip-lr` | **只翻左右** | 站在机器人**背后**（只有左右反、前后本来就对） |

**实际使用的相机位于机器人背后**，属于后一种情况，因此正确参数是 `--flip-lr`。
若误用 `--behind`，会把本来正确的前后方向翻反。

## 7. 经验总结

1. **视角镜像要考虑所有涉及水平面的自由度。**
   平移的左右和旋转的 yaw 属于同一类镜像，设计时容易只想到前者而遗漏后者。

2. **坐标系转换中，"绕世界轴"与"绕自身轴"是两种本质不同的语义。**
   对于人体/机械臂的直觉操作，通常应使用**绕自身轴（右乘）**，
   这样手感才能保持一致；绕世界轴会导致"姿态越歪手感越怪"。

3. **底座朝向的微小偏斜（约 3°）会放大坐标系误用的问题。**
   即使看起来"差不多对齐"，用世界轴近似末端轴仍会产生可见偏差。

4. **"按某个开关无效"本身就是重要线索。**
   当切换视角对某个方向完全没有影响时，说明该方向**根本没有接入视角逻辑**，
   而不是视角参数选错了。这一判断大幅缩短了排查时间。
