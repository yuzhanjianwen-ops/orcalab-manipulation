```
robot aabb: [17.926, -5.170, 0.015]  ->  [18.981, -1.615, 2.258]
  x 中心 18.45  |  y 中心 -3.39  |  顶部 z 2.26
```

### 欧拉角约定（踩过坑，务必记住）

**OrcaStudio 的 `rotation = [pitch(X), yaw(Y), roll(Z)]`** —— 和常见直觉不一样，是实测出来的：

| 分量 | 轴 | 作用 |
|---|---|---|
| `rotation[0]` | **X** | 抬头 / 低头（pitch）|
| `rotation[1]` | **Y** | 左右转向（yaw）|
| `rotation[2]` | **Z** | **画面翻滚（roll）← "歪"就是它** |

相机**默认朝 -X** 方向。

验证方法：在固定位置分别给单轴 +20°，看画面变化——
`X+20` 是俯仰、`Y+20` 是左右、`Z+20` 是画面整体倾斜。

### 摆正公式（想让相机看向 `[tx,ty,tz]`）

```
d = target - pos
horiz = hypot(dx, dy)

yaw   = atan2(dy, dx) - 180          # 相机朝 -X，所以要减 180
pitch = -atan2(dz, horiz)             # 俯角为正
roll  = 0                             # 想不歪，必须为 0
```

本次代入：`pos=[18.45,-3.35,2.15]`，`target=药盒=[17.149,-2.935,1.241]`
→ **pitch=33.65°，yaw=-17.69°，roll=0°**，已写入 Actor。

> **踩坑记录**：最初我把朝向写成 `[0, -33.6, 162.3]`——yaw 和 pitch 放反了轴，`roll` 还留了 162°。
> 结果画面被翻了 162 度，看着就是"歪的"。修正后 roll=0，就正了。

## 十一、方案A(挂到手臂)到底能不能采数据？—— 实测结论

**结论：方案A 能让相机跟着手臂动，但"能跟随" ≠ "能采到图"。**
**采集走的是 WebSocket 推流，现在推流根本没开 —— 这才是卡点。**

### 11.1 关键发现：相机资产的推流配置

### 11.5 reparent 的实测结果

`reparent_actor` 可用，但**只能挂到 GroupActor 下**：

```
reparent -> /dual_arm_collaborative_service_robot_1
   ✅ 成功（机器人是 AssetActor，被当成可挂载节点）

reparent -> /dual_arm_.../mujoco_wrap/rootPrim/robot_holder1
   ❌ 失败：Parent must be a GroupActor.
```

**问题**：`arm_r_end_link` 这些是机器人内部的 **entity**，不是场景里的 Actor。

只能挂到整个机器人根节点 → 相机跟着机器人**整体**动，
**但不会跟着某条手臂单独动**。

> 想真正做"腕部相机跟随手腕"，得改资产的 MuJoCo XML，
> 在 `arm_r_end_link` 的 body 里加 `<camera>` 定义。
> 这是改资产，不是改场景 —— 属于甲方资产的范畴。

## 十二、(a) 深挖推流服务 —— 找到了！★★★

### 12.1 关键结论

**源码里写得很直白**（`orca_gym/environment/euler/orca_gym_euler_env.py`）：

> Studio 端 MuJoCo `<camera>` **默认不推送** WebSocket RGB/Depth 流，
> **必须通过本方法显式激活**后，对应端口（如 7070/7071）才会监听并推流。

**"推流服务"= OrcaStudio 内部的一个 WebSocket 服务端，需要主动激活。**

### 12.2 怎么激活：一个 gRPC 调用

```python
stub.SetCameraSensorInfo(SetCameraSensorInfoRequest(
    actor_name="...", capture_rgb=True, capture_depth=True,
    color_port=7070, depth_port=7071, ...))
```

### 12.3 实测进展（一步步）

| 步骤 | 状态 |
|---|---|
| 启动仿真 | ✅ `50051` gRPC 通了 |
| **7070/7071 端口监听** | ✅ **开了！**（之前是 False）|
| WebSocket 握手 | ✅ **成功**（`ws://localhost:7070`）|
| 收到视频帧 | ❌ **5 秒无数据** —— 缺"激活"这步 |
| `SetCameraSensorInfo` | ❌ `Camera actor name not found`（穷举 40+ 名字全失败）|

### 12.4 为什么 `actor_name` 找不到

源码说得很清楚：**Studio 端必须有 MuJoCo `<camera>` 传感器**。

而我们查过：**机器人模型 `ncam=0`** —— **一个相机传感器都没有**。

相机资产（`camera/camera`）只是个**几何体**，里面**没有 `<camera>` 标签**。
所以 `SetCameraSensorInfo` 找不到任何可激活的相机。

**这解释了整条链路为什么断在这** —— 不是我们操作不对，
是**资产里根本没有相机传感器定义**。

### 12.5 ★ 但是！找到了立刻能用的取图接口

翻 gRPC 的 101 个方法时，发现了 **`GetCameraFramePNG`**：

```python
stub.GetCameraFramePNG(GetCameraFramePNGRequest(image_path=目录))
```

**实测结果**：一次调用同时生成 **4 种图**（不是 1 张）：

```
<outdir>/
    color/AgentCamera_color_0.png             RGB        1080x1080 RGBA
```

# 十五、相机推流完整机制（2026-10-02 实测打通认知）

## 15.1 结论先行

**相机的正确用法是一条「双通道」链路，两个条件缺一不可：**

```
                 ┌─────────────── 通道 A：引擎层（O3DE）───────────────┐
                 │  CameraPipeline 组件（资产自带）                     │
                 │  Enable / ColorCamera / DepthCamera / 分辨率 ...     │
                 │  → 打开后引擎启动 NVENC 硬件编码器                    │
                 └──────────────────────────────────────────────────┘
                                        +
                 ┌─────────────── 通道 B：MuJoCo 层 ───────────────────┐
                 │  MuJoCo 模型里的 <camera> 传感器（ncam > 0）          │
                 │  → 通过 gRPC SetCameraSensorInfo 激活 WebSocket 推流  │
                 │  → ws://localhost:<color_port>  收 H.264 裸流         │
                 └──────────────────────────────────────────────────┘
```

**我们卡在通道 B**：模型 `ncam = 0`，所以 `SetCameraSensorInfo`
永远返回 `Camera actor name not found`。

## 15.2 铁证：官方源码原文

`orca_gym/core/euler/orca_studio_bridge.py` 里
`set_camera_sensor_info` 的文档字符串**白纸黑字写着**：

> **"Studio 端 MuJoCo `<camera>` 默认不推送 WebSocket RGB/Depth 流，
> 必须通过本方法显式激活后，7070/7071 等端口才会监听并推流。"**

这一句话同时解释了三个之前的困惑：

1. 为什么属性面板里 `Enable=true` 了，7070 还是连不上；
2. 为什么 7070 用普通 `socket.connect()` 测是 closed；
3. 为什么官方代码里从来不是"打开属性就行"。

## 15.3 推流数据格式（`orca_gym/sensor/rgbd_camera.py`）

官方 `CameraWrapper.do_stuff()` 是最权威的客户端实现：

```python
uri = f"ws://localhost:{self.port}"
async with websockets.connect(uri) as websocket:
    data = await websocket.recv()
    data = data[8:]                # ← 前 8 字节 = 时间戳
    rawData.write(data)            # ← 之后是 H.264 裸流
    container = av.open(rawData, mode='r')   # ← PyAV 解码
    frame.to_ndarray(format='bgr24')
```

**协议总结：**

| 项 | 值 |
|---|---|
| 传输 | **WebSocket**（不是 TCP 裸端口）|
| 地址 | `ws://localhost:<color_port>` |
| 分帧 | 每帧 = **8 字节小端时间戳** + H.264 数据 |
| 编码 | H.264（NVENC 硬编，`h264_nvenc`）|
| 解码 | PyAV（`av`）+ OpenCV |
| 深度 | 另一个端口 `<depth_port>`，同样方式 |
