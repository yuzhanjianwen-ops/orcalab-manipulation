# 移植性说明：本模块能否在其他电脑上运行？

> 结论先行：**代码可以，环境需要配套。** 本文件夹已完全自包含，
> 但运行仍依赖三个「文件夹之外」的条件，详见下文。

## 一、最简结论

| 问题 | 答案 |
|---|---|
| 代码拷过去能直接用吗？ | ✅ 能，零外部路径依赖 |

## 三、为什么「必须有仿真端」

`teleop.py` **不是**独立程序，它是**客户端**：

```
┌─────────────────┐   gRPC    ┌──────────────────┐
│   teleop.py     │ ────────► │  OrcaLab 仿真端   │
│  (本模块/客户端) │  50051    │  (机器人+物理)    │
└─────────────────┘           └──────────────────┘
```

仿真端没启动会直接报错：

```
grpc.aio._call.AioRpcError: <AioRpcError of RPC that terminated with:
  details = "failed to connect to all addresses; last error:
             UNAVAILABLE: ipv4:127.0.0.1:50051: ConnectEx:
             Connection refused (No connection could be made ...)"
```

**排查方法**：确认 50051 端口在监听。

```powershell
netstat -ano -p TCP | Select-String "50051"
```

## 四、为什么用键盘模式就能绕开手柄

| | 手柄 | 键盘 |
|---|---|---|
| 读取方式 | `XInputGetState` | `GetAsyncKeyState` |
| 是否需要硬件 | ✅ 需要手柄 | ❌ 只需键盘 |
| 是否需装库 | ❌（纯 ctypes） | ❌（纯 ctypes） |

两套输入都**不需要安装任何第三方库**，这正是键盘方案能作为"无手柄备选"的原因。

## 五、移植步骤

### 步骤 1：拷文件夹

把整个 `teleop/` 拷到新机器任意位置（**路径可以不同**，代码里没有硬编码路径）。

### 步骤 2：装 Python 环境

**推荐**：直接克隆现有环境

```powershell
conda create -n orcalab --clone orcalab
```

**或者**：按甲方文档装 `orca_gym`，再补：

```powershell
pip install numpy scipy
```

> ⚠️ `orca_gym` 版本必须与仿真端一致。
> 甲方明确提过：**7.x 与 8.x 的相机接口不兼容**，之后以 8.x 为准。

### 步骤 3：启动仿真端

打开 OrcaStudio，加载场景，确认 50051 在监听。

### 步骤 4：先跑不需要仿真的自检

```powershell
cd teleop
python -X utf8 tests\test_keypad.py
```

预期：`54 passed, 0 failed`。
这一步能过，说明代码 + Python 环境 OK。

### 步骤 5：连接仿真运行

```powershell
python -X utf8 -u teleop.py --keyboard --flip-lr
```

## 六、本文件夹的「自包含」是怎么做到的

原本 `orca_rig.py` 里有一行硬编码路径：

```python
LEGACY_WORK = r"<项目目录>"
```

它只用来定位 `gripper_table.json`。移植时已改为：

```python
ASSETS_DIR = os.path.join(HERE, "assets")
GRIPPER_TABLE_PATH = os.path.join(ASSETS_DIR, "gripper_table.json")
```

并删除了已无用途的 `LEGACY_WORK`（检查过：没有从那个目录 import 任何模块）。

**验证结果**：全目录扫描，外部绝对路径数量 = **0**。

测试脚本也加了路径引导，可在任意工作目录下运行：

```python
_ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
if _ROOT not in _sys.path:
    _sys.path.insert(0, _ROOT)
```

## 七、已知不可移植项

| 项 | 原因 | 对策 |
|---|---|---|
| 操作系统 | `xinput1_4.dll` / `user32.GetAsyncKeyState` 是 Win32 API | 换 Linux 需重写输入层 |
| `orca_gym` | 甲方私有 SDK，pip 装不到 | 找甲方要，或克隆环境 |
| 仿真端 | 独立软件 | 新机器也要装 OrcaStudio |
| 端口 50051 | 固定写死 | 一般不用改；如需改在 `orca_rig.py` 的 `ORCAGYM_ADDR` |

## 补充（2026-09-26）：新电脑 / 新场景适配

### Q：新用户环境已配好，用本文件夹能否直接开始控制机器人？

**答：多数情况可以直接开始；但有两个「场景相关」的值需要注意。**

代码在**命名层面是自适应的**，只有两处绑定到具体场景。

### ✅ 自动适配的部分（无需改动）

`orca_rig.py` 用**按名字自动发现**的方式索引机器人，没有写死索引号：

```python
# 自动搜索 arm_l_joint1..7
cands = sorted(n for n in self.joints if f"arm_{side}_joint{k}" in n)
if not cands:
    raise RuntimeError(f"missing arm_{side}_joint{k}")
```

* 双臂关节、夹爪关节：**按名字前缀自动找**
* 场景里的可动物体（药盒/药瓶/托盘）：**连接时自动快照**，不写死物体名
* 因此**布局不同也能跑**（只要机器人命名规范一致）

### ⚠️ 需要注意的两处（这两处绑定场景）

| 项 | 默认值 | 何时需要改 |
|---|---|---|
| `env_index` | **93** | 新电脑的场景索引不同 |
| `agent` | `dual_arm_collaborative_service_robot_1` | 机器人对象名不同 |

**这两个值原先写死在代码里，现已支持命令行覆盖**（默认值不变，老用法不受影响）：

```powershell
python -X utf8 -u teleop.py --keyboard --flip-lr `
    --env-index 93 `
    --agent dual_arm_collaborative_service_robot_1 `
    --addr localhost:50051
```

| 参数 | 说明 |
|---|---|
| `--env-index` | 仿真场景索引 |
| `--agent` | 场景里机器人的名字 |
| `--addr` | OrcaLab gRPC 地址（默认 `localhost:50051`）|

### 出错了怎么判断

`orca_rig.py` 会明确报出缺什么：

| 报错 | 含义 | 处理 |
|---|---|---|
| `missing arm_l_joint1` | 场景里没有 `arm_l_joint*` 关节 | 确认机器人对象命名，或用 `--agent` 指定 |
| `missing gripper_r inner_joint1` | 夹爪命名不符 | 同上 |
| `Connection refused :50051` | 仿真端没开 / 地址不对 | 开仿真，或 `--addr` 指定 |

在 OrcaStudio 里能看到当前场景的索引。
