# 数据采集使用说明

> 对应脚本：`collect.py`（总装）｜创建：2026-09-28｜最后更新：2026-10-15

---

## 一、先启动 OrcaStudio

采集脚本**不自己起仿真**，它连的是你已经打开的那个 OrcaStudio 场景
（gRPC `localhost:50051`）。

所以顺序是：

1. **先打开 OrcaStudio**，加载好场景，等机器人出现
2. 再运行 `collect.py`

> 如果 OrcaStudio 没开，会看到 `ConnectionRefused`。

---

## 二、启动命令

```powershell
cd <项目目录>

# 手柄（相机在你背后看时加 --flip-lr）
& "<你的orcalab环境>\python.exe" -X utf8 -u collect.py --flip-lr

# 键盘（没手柄时）
& "<你的orcalab环境>\python.exe" -X utf8 -u collect.py --keyboard --flip-lr

# 换数据集目录 / 任务名
& "...python.exe" -X utf8 -u collect.py --dataset D:\data\pick --task pick_medbox
```

**不要加 `--no-render`**，除非你只想测时间——加了画面就不刷新。

## 三、按键流程

### 采集按键（十字键）

| 按键 | 手柄 | 键盘 | 作用 |
|---|---|---|---|
| **十字下** | D-pad ↓ | **K** | 进入待命 / 取消 / 录制中途中止 |
| **十字上** | D-pad ↑ | **I** | 开始 / 结束录制（复用）|
| **十字左** | D-pad ← | **J** | 保存 |
| **十字右** | D-pad → | **L** | 丢弃 |

### 一次完整的采集

```
[IDLE]  正常遥操作
   │  按【十字下】进入待命
   ▼
[READY] 已武装
   │  按【十字上】开始录
   ▼
[REC]   正在录制 —— 操作机器人完成任务
   │  按【十字上】结束
   ▼
[REVIEW] 待判定
   ├─ 按【十字左】→ 保存到磁盘 → 回到 IDLE
   └─ 按【十字右】→ 丢弃        → 回到 IDLE
```

**安全设计**（防误触）：

- `IDLE` 时十字上/左/右**全部无效**，必须先按十字下
- `READY` 时再按十字下 = 取消待命
- `REC` 中按十字下 = **强制中止并丢弃**（这条数据不要了）
- 只有 `REVIEW` 里按十字左才真正写盘，其它情况数据只在内存

### 原有的遥操作按键完全不受影响

`A/B` 夹爪、`X` 切换手臂、`Y` 回工作位、`START` 重新同步、
`BACK` 急停，以及左右摇杆的运动控制，**和 `teleop.py` 一模一样**。

### 复位键（重要）

原本「十字下」在 `teleop.py` 里是**全场景重启**（物体 + 双臂 + 夹爪回起点）。
采集模式下十字下归采集状态机，**不能再兼作重启**，所以复位挪到了独立键：

| 设备 | 复位键 | 说明 |
|---|---|---|
| **手柄** | **RSTICK**（右摇杆按下去）| 单击触发 |
| **键盘** | **N** | 按一下触发 |

**复位键在采集过程中也能用**（2026-09-28 起）：

| 状态 | 按复位键的效果 |
|---|---|
| `IDLE` | 全场景复位 |
| `REC`（录制中）| **也复位**，并且**数据继续记录** —— 复位这件事本身也会被记进数据 |
| `READY` / `REVIEW` | 复位 |

这样你可以在**一个 episode 里连续做多次**「抓取 → 放下 → 复位 → 再抓」，
不用中断录制。

**复位动作会被记录**：每帧里存了一个 `n_resets` 字段，记录到那一刻为止
复位了几次。后续想按复位点切分成多条短 episode 时，用这个字段即可。

如果**不想要**录制中复位（怕误触），加 `--no-reset-in-rec`：

```powershell
& "<你的orcalab环境>\python.exe" -X utf8 -u collect.py --keyboard --flip-lr --no-reset-in-rec
```

用 `--reset-key` 可以改复位键，例如改用 H 键：

```powershell
& "<你的orcalab环境>\python.exe" -X utf8 -u collect.py --keyboard --flip-lr --reset-key H
```

> 注意：Python 解释器要写**完整路径** `<你的orcalab环境>\python.exe`，
> 不能简写。

## 四、数据存哪、什么格式

### 目录

```
<dataset_path>/                     ← 默认 scripts/collect/dataset
    2026-09-28_164713_96b72dde/     ← 每条 episode 一个目录，名字带采集时间
        episode.hdf5                    实际数据（HDF5）
        meta.json                       元信息
```

**目录命名规则**：`<日期>_<时分秒>_<8位随机码>`

- `2026-09-28_164713_96b72dde` = 2026-09-28 16:47:13 采集
- 时间在前 → **按名字排序就等于按时间排序**，一眼看得出先后
- 末尾随机码防止同一秒内重名

**怎么找数据**：本目录下有 **`DATASET_LOCATION.txt`**，记录最新数据集位置。

```powershell
# 直接打开数据文件夹
explorer "<项目目录>"
```

### episode.hdf5 结构

```
observations/
    joint_pos      (T, 14)   双臂 7+7 关节角
    joint_vel      (T, 14)   双臂 7+7 关节角速度
    gripper_pos    (T, 16)   双夹爪 8+8 关节角
    ee_pos         (T, 6)    双臂末端位置 xyz
    ee_quat        (T, 8)    双臂末端姿态四元数 xyzw
    image          (T,H,W,3) ← 仅相机连通时才有
actions/
    pos            (T, 3)    活动臂末端目标位置
    quat           (T, 4)    活动臂末端目标姿态 xyzw
    rot6d          (T, 6)    目标姿态 6D（加 --rot6d 才有）
    gripper        (T,)      夹爪开合指令
timestamp          (T,)      相对录制开始的秒数
active_arm         (T,)      0=左臂 1=右臂

属性：task_name / episode_id / n_frames / success / duration / created_at / source
```

`meta.json` 示例（记录了采集时间与字段形状）：

```json
{
  "episode_id": 0,
  "episode_dir": "2026-09-28_164713_96b72dde",
  "collected_at": "2026-09-28 16:47:13",
  "n_frames": 1471,
  "success": true,
  "duration": 91.9,
  "task_name": "teleop",
  "fields": { "joint_pos": [1471, 14], ... }
}
```

### 快速看一眼采到的数据

```powershell
& "<你的orcalab环境>\python.exe" -X utf8 -c @"
import h5py, glob, os
d = sorted(glob.glob(r'<项目目录>'))[-1]
print(os.path.basename(d))
with h5py.File(os.path.join(d,'episode.hdf5'),'r') as f:
    f.visititems(lambda n,o: print(' ', n, o.shape) if hasattr(o,'shape') else None)
    print('  attrs:', dict(f.attrs))
"@
```

## 五、相机

> **后续进展（2026-10-15）**：本节原有结论「当前还没有相机」已被推翻。场景里**有** 3 台机载相机
> （`camera_head` / `camera_left` / `camera_right`）。左右腕两台取图与编辑器视口一致；
> 头部相机因父节点 `scale` 未正确乘入相机偏移，画面落在头部外壳内壁。
> 完整根因、实测证据与修复方案见
> [`../scripts/collect/相机取图根因结论与修复方案.md`](../scripts/collect/相机取图根因结论与修复方案.md)。

### 5.1 现状

| 相机 | 取图状态 | 说明 |
|---|---|---|
| `camera_left` / `camera_right` | 正常 | 与编辑器视口构图一致（实测差异度 23.9 / 22.9） |
| `camera_head` | 待修复 | 画面为机器人头部外壳内壁；需在 OrcaStudio 里把相机沿视线外移约 0.3 m |

### 5.2 两种取图链路

| 方式 | 参数 | 帧率 | 说明 |
|---|---|---|---|
| WebSocket 推流 | `--cam3-ws`（默认） | 30 Hz | 机载三相机，快；受上述位姿问题影响 |
| 引擎离屏渲染 | `--cam3` | 约 0.6 fps | 慢，用于校验构图 |

采到的图像按帧写入 `observations/image`（HDF5），或落成 `videos/`（LeRobot）。

### 5.3 相机是解耦的

**任何一路相机连不上都会自动降级**并打印原因，不会崩，只是 episode 里少了对应的图像字段。

```powershell
& "...python.exe" -X utf8 -u collect.py --flip-lr --cam3-ws
```

这是刻意做的「相机解耦」设计——相机不阻塞采集流程，没有图像也能照常录状态与动作。

## 六、命令行参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--dataset` | `./dataset` | 数据集目录 |
| `--task` | `teleop` | 任务名，写进 meta |
| `--rot6d` | 关 | 额外存 `action_rot6d` |
| `--camera PORT` | 无 | 相机 WebSocket 端口，如 7070 |
| `--keyboard` | 关 | 用键盘代替手柄 |
| `--reset-key` | RSTICK / N | 复位键名 |
| `--no-reset-in-rec` | 关 | 禁止录制中复位 |
| `--flip-lr` | 关 | 相机在机器人背后时镜像左右 |
| `--flip-fb` | 关 | 只镜像前后 |
| `--behind` | 关 | 你在机器人对面看 |
| `--view` | 无 | 预设名 front/behind/flip-lr/flip-fb |
| `--index` | 0 | 手柄槽位 |
| `--no-render` | 关 | 不渲染（只测时间）|
| `--env-index` / `--agent` / `--addr` | 内置 | 场景索引 / 机器人名 / gRPC 地址 |

## 七、实测结果（2026-09-28）

**端到端验证通过**：

| 项 | 结果 |
|---|---|
| 控制循环帧率 | ~19.5 fps（`--no-render`）|
| OSC 末端误差 | ~2.0 mm |
| 保存路径 | ✅ 正确写盘 |
| 录制中途中止 | ✅ 不写盘 |
| 录完丢弃 | ✅ 不写盘 |
| 落盘字段 | ✅ 全部形状正确（见第四节）|

**测试用例覆盖**：
- 正常流程：待命 → 录制 120 帧 → 保存 → 目录数 = 1
- 中途中止：录制 50 帧 → 十字下 → 目录数仍 = 1
- 录完丢弃：录制 30 帧 → 十字右 → 目录数仍 = 1

## 八、常见问题

**Q：报 `no XInput gamepad in slot 0`**
手柄没连上或没唤醒。摇一下摇杆，或者用 `--keyboard`。

**Q：报 `ConnectionRefused`**
OrcaStudio 没开，或场景没加载完。先开 Studio。

**Q：按了十字键没反应**
- 手柄：确认十字键本身能用（在 `teleop.py` 里试）
- 键盘：采集键是 **I / K / J / L**，不是 WASD
- `IDLE` 状态下只有十字下有效，这是防误触设计

**Q：想同时录左右两条手臂**
当前一次只录**活动臂**的 action，但 `observations` 里**双臂状态都完整记录**。
所以训练时两条手臂的观测都有，动作只标了活动臂（用 `active_arm` 区分）。

**Q：数据能直接给 LeRobot 用吗**
可以，**LeRobot v3.0 直存已实现**（`collect_lerobot.py` + `saver_lerobot.py`），
产出标准 parquet + mp4 数据集，可直接用于训练，详见 [`LeRobot3.0采集使用说明.md`](LeRobot3.0采集使用说明.md)。

不指定 `--lerobot-out` 时仍走 HDF5；也可以显式加 `--no-lerobot` 强制回到 HDF5 格式。
