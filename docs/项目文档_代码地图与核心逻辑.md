## 一、项目总览

本项目做两件事：

```
① 遥操作  ——  用手柄 / 键盘控制双臂机器人
② 数据采集 ——  把遥操作过程录下来，存成数据集
```

两者共用一套"连接仿真 + 控制机器人"的底层（`orca_rig.py`）。

```
                    ┌──────────────────────┐
                    │   OrcaLab / OrcaStudio │  （外部仿真程序，需先启动）
                    │   gRPC localhost:50051 │
                    │   MCP  localhost:12345 │
                    └───────────┬──────────┘
                                │
                    ┌───────────▼──────────┐
                    │      orca_rig.py      │  连接 / 读状态 / 下发控制
                    └───────┬───────┬──────┘
                            │       │
              ┌─────────────▼──┐ ┌──▼──────────────┐
              │   遥操作模块    │ │   数据采集模块   │
              │  teleop.py     │ │  collect.py     │
              │  gamepad.py    │ │   ├ recorder.py │
              │  keypad.py     │ │   ├ keymap.py   │
              └────────────────┘ │   ├ fields.py   │
                                 │   └ saver_hdf5  │
                                 └─────────────────┘
```

## 四、核心业务逻辑

### 4.1 采集状态机（四个状态）

```
[IDLE]  正常遥操作，不记录
   │  按【十字下】/ K
   ▼
[READY] 已武装，等待开始
   │  按【十字上】/ I
   ▼
[REC]   正在录制 —— 操作机器人完成任务
   │  按【十字上】/ I
   ▼
[REVIEW] 待判定
   ├─ 按【十字左】/ J → 保存到磁盘 → 回 IDLE
   └─ 按【十字右】/ L → 丢弃        → 回 IDLE
```

**安全设计（防误触）**：

| 状态 | 行为 |
|---|---|
| `IDLE` | 十字上/左/右**全部无效**，必须先按十字下 |
| `READY` | 再按十字下 = 取消待命 |
| `REC` | 按十字下 = **强制中止并丢弃** |
| 数据写盘 | **只有 `REVIEW` 里按十字左才真正写盘**，其它时候只在内存 |

### 4.2 按键映射

| 功能 | 手柄 | 键盘 |
|---|---|---|
| 待命 / 取消 / 中止 | 十字下 ↓ | **K** |
| 开始 / 结束录制 | 十字上 ↑ | **I** |
| 保存 | 十字左 ← | **J** |
| 丢弃 | 十字右 → | **L** |
| 复位（全场景重开）| 右摇杆按下 | **N** |

**遥操作键（不受采集影响）**：`A/B` 夹爪、`X` 切换手臂、`Y` 回工作位、`START` 重新同步、`BACK` 急停、左右摇杆控制运动。

### 4.3 复位机制

- 原本"十字下"在纯遥操作里是全场景重启；采集模式下该键归状态机，**复位挪到独立键**
- **录制中也能复位**，且**复位动作本身会记进数据**（`n_resets` 字段）
- 效果：可以一个 episode 里连续做「抓取 → 放下 → 复位 → 再抓」
- 不想要录制中复位 → 加 `--no-reset-in-rec`
- 想连续切分多条短 episode → 用 `n_resets` 字段切

### 4.4 控制算法（OSC）

- 用**甲方 `OrcaManipulation` 仓库的 `OSC_POSE` 控制器**（`orca_gym` 自带）
- 参数：`kp=400`（甲方默认 150 → 稳态误差 11.4mm；400 → 6.6mm，力矩饱和 0.3%）
- **关键发现**：关节交接方式决定成败——
  - 从任意姿态用 PD 慢慢过渡到 NEUTRAL → 抖动 8.0 mm
  - **先瞬移到 NEUTRAL 静置 2s，再建 OSC → 0.05 mm**
- IK+PD 与 OSC **互补**：IK 有解时更精确（0.0 mm）；IK 陷入局部极小时 OSC 更稳

### 4.5 视角镜像（重要）

相机在机器人**背后**时，左右/前后会反，需加 `--flip-lr`：

| 标志 | 适用场景 |
|---|---|
| `--flip-lr` | **相机在机器人背后**（当前配置，已验证）|
| `--behind` | 背后视角 |
| `--flip-fb` | 前后翻转 |

**涉及的方向**：左右平移、yaw（水平旋转）镜像；pitch / roll 不动。

## 五、如何运行

### 启动顺序（**必须先做第 1 步**）

```
1. 打开 OrcaLab，加载 SimpleMovement2.json，点【运行仿真】
2. 确认场景里有：机器人 + 药盒 + 药瓶 + 托盘
3. 再运行下面的命令
```

> 采集/遥操作脚本**不自己起仿真**，连的是你已打开的 `localhost:50051`。
> 没启动会报 `ConnectionRefused`。

### 遥操作

```powershell
cd <项目目录>

# 手柄
& "<你的orcalab环境>\python.exe" -X utf8 -u teleop.py --flip-lr

# 键盘
& "<你的orcalab环境>\python.exe" -X utf8 -u teleop.py --keyboard --flip-lr
```

### 数据采集

```powershell
cd <项目目录>

# 手柄采集
& "<你的orcalab环境>\python.exe" -X utf8 -u collect.py --flip-lr

# 键盘采集
& "<你的orcalab环境>\python.exe" -X utf8 -u collect.py --keyboard --flip-lr

# 自定义目录 / 任务名 / 6D 姿态
& "...python.exe" -X utf8 -u collect.py --keyboard --flip-lr --dataset D:\data\pick --task pick_medbox --rot6d
```

### 相机相关

```powershell
cd <项目目录>

# 相机体检
& "...python.exe" -X utf8 -u camera_verify.py

# 开相机 Enable
& "...python.exe" -X utf8 -u camera_verify.py --on

# 取图
& "...python.exe" -X utf8 -u camera_verify.py --grab
```

### 相机问题的技术定位（截至 2026-10-15）

| 层 | 有什么 | 状态 |
|---|---|---|
| prefab 定义 | `camera_head` + `CameraPipeline` + `CameraStreamTopic` | 有 |

| 属性可写 | `Enable=True`、`ColorPort=7070` | 写入成功 |
| WebSocket 推流 | 7070 / 7080 / 7090 | 可用（30 Hz）；受头部相机位姿问题影响 |

**真正根因**：三台机载相机挂在父节点 `/dual_arm_collaborative_service_robot_1` 下，

实测所需补偿量 `|Δ| ≈ 0.83 m`，与理论值 `(1 − 1/1.6954) × 2.117 m = 0.868 m` 吻合到 5% 以内。

完整证据链、网格搜索结果与两种修复方案见
[`../scripts/collect/相机取图根因结论与修复方案.md`](../scripts/collect/相机取图根因结论与修复方案.md)。
修复后可用 `scripts/collect/_verify_cam_fix.py` 一键验收（输出三联对照图，diff < 40 记 PASS）。
